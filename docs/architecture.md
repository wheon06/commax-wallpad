# 코드 구조

| 파일 | 책임 |
|---|---|
| `models.py` | 연결 설정·채널 번호 검증, 상태 모델 |
| `protocol.py` | SOAP 요청 생성·응답 검증 |
| `api.py` | aiohttp HTTP forward proxy 전송 |
| `coordinator.py` | 폴링, 직렬화, 제어 후 실제 상태 확인 |
| `config_flow.py` | 수동 설정·기존 파일 가져오기·옵션·재인증·재구성 |
| `registry.py` | 설정에서 제거되거나 유형이 바뀐 채널의 이전 엔티티 정리 |
| `entity.py`, `light.py`, `fan.py` | Home Assistant 기기·전등·팬 모델 |
| `diagnostics.py` | 허용 목록 기반의 비식별 진단 |
| `capture.py` | 의존성 없는 로컬 패킷 분석 |
| `tools/` | 로컬 설치·백업·정리·배포 도구 |

프로토콜 모듈에는 Home Assistant 의존성이 없습니다. 새 설치의 식별자는 프록시·SOAP 주소에서 해시로 생성하지만, 0.1에서 이미 사용하던 식별자는 그대로 유지합니다. 타입이 변하지 않은 채널은 기존 엔티티 ID를 유지합니다. 타입 변경 시 해당 채널의 이전 도메인 엔티티를 제거하고 새 도메인 엔티티를 만듭니다.

폴링과 제어는 같은 잠금을 사용해 오래된 조회가 제어 결과를 덮어쓰지 않도록 합니다. 프록시가 연결되지 않으면 한 주기에서 나머지 채널로 같은 오류를 반복하지 않습니다. 채널별 프로토콜 오류는 해당 채널의 사용 불가 상태로 구분합니다. 요청별 제한 시간은 10초, 전체 폴링은 30초입니다.

제어는 명령 한 번과 조회 최대 다섯 번으로 구성하며, 상태가 바뀌지 않으면 성공으로 처리하지 않습니다. 배기는 현재 확인된 binary-light SOAP 필드만 사용하며 속도·색온도 등은 구현하지 않습니다.

설정 파일과 Home Assistant의 `.storage`는 사용자 데이터입니다. 배포 코드는 이를 포함하지 않습니다. HACS 설치 ZIP에는 `custom_components/commax_wallpad`의 실행 파일만 포함합니다.
